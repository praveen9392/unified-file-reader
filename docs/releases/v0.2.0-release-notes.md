# Release v0.2.0: Enterprise Exception Handling & Logging Standards

## Summary
Version **0.2.0** introduces production-grade, enterprise exception handling and structured logging standards across the library following clean architecture and SOLID principles. It maintains **100% backward compatibility** for all existing client code while unlocking stable error codes, context serialization, and root-cause preservation.

---

## What's Changed

### 🚀 New Features & Architecture
- **Unified Base Exception**: Added `ApplicationException` with stable `error_code`, `details`, and `.to_dict()` JSON-ready serialization.
- **Domain vs Infrastructure Separation**:
  - `BusinessException`: `UnsupportedFormatError`, `BusinessValidationException`, `ResourceNotFoundException`.
  - `InfrastructureException`: `FileReaderException`, `PDFReadException`, `CSVReadException`, `ExcelReadException`, `DOCXReadException`, `JSONReadException`, `TextReadException`.
- **Exception Chaining**: All format readers use `raise ... from exc` to guarantee root cause tracebacks are never lost.
- **Production Logging**: Parameterized logging using `logger.exception()` across all format reader modules.
- **100% Backward Compatibility**: `ReaderError`, `FileReadError`, `UnsupportedFormatError`, and `json.JSONDecodeError` retain identical behavior.

### 🧪 Quality Assurance & Testing
- **New Unit Test Suite**: Added `tests/test_enterprise_exceptions.py` covering hierarchy inheritance, error code formatting, and exception chaining (**100 tests passing**).
- **Manual Integration Testing**: Added `manual_test/test_all_types.py` benchmarking CSV, JSON, TXT, XLSX, PDF, and DOCX using real-world downloaded datasets.
